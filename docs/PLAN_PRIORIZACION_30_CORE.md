# Plan para priorizar 30 HU core, sin incrementar artificialmente el alcance

La guía V4 requiere 30 HU core funcionales en web. La lista preliminar anterior contiene 22 candidatas: HU-007, HU-023 y HU-031 a HU-050. Su inclusión no demuestra automáticamente que todas tengan ambos escenarios cubiertos ni que sean 22 capacidades independientes.

Actualmente se verificaron localmente ambos escenarios de 13 HU: HU-031, HU-035, HU-037, HU-038, HU-040, HU-042, HU-044, HU-045, HU-046, HU-047, HU-048, HU-049, HU-050.

## Orden de trabajo propuesto
1. Revisar y aprobar el conjunto core con el backlog y el equipo, sin transformar HU de marketing, login o navegación trivial en core.
2. Resolver primero defectos de las 22 candidatas: fotografías para HU-032, comportamiento de ruta ficticia y límites de HU-034, ausencia de servicio de sincronización HU-039, primera configuración HU-041 y escenarios alternativos no probados.
3. Revisar las HU-001–HU-030 para detectar capacidades adicionales auténticamente core que estén respaldadas por el Product Backlog. No seleccionar historias solo para sumar números.
4. Incorporar pruebas para ambos escenarios de cada HU priorizada y guardar capturas/registro.
5. Validar el resultado sobre la web publicada; las pruebas en memoria no sustituyen pruebas finales.

**Decisión pendiente:** 30 HU core definitivamente priorizadas no comprobadas; registrar la aprobación del equipo antes de declarar cumplimiento.
